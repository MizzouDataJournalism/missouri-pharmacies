# Mapping Missouri pharmacies

### Selecting and locating pharmacies
We analyzed the driving times to Class A pharmacies, or [pharmacies that are required to provide services to the general public](https://pr.mo.gov/boards/pharmacy/practiceguide.pdf), in Missouri to determine how many people in the state live far away from these facilities. 
We obtained a list of pharmacies from the Missouri Board of Pharmacy. The data is dynamic, so the analysis is accurate as of April 24. The dataset had pharmacy addresses, so the first step was geocoding them into latitude and longitude points, using the R library [ggmap](https://github.com/dkahle/ggmap), which uses the geocoding API from Google (see [scripts/001_geocode.R](scripts/001_geocode.R)). 
One of the pharmacies did not return its latitude and longitude values, and a handful of other pharmacies were flagged during the geocoding process. We looked up each of those pharmacies and added new values. We also categorized all of the pharmacies into three groups based on their belonging to some of the most common pharmacy chains in Missouri: Walgreens, CVS or Other. 

### Mapping drive-time polygons
Next ([scripts/002_get_isolines.R](scripts/002_get_isolines.R)) we used the hereR package wrapper for the [HERE](https://www.here.com/) Technologies API, this to create drive time isolines for each pharmacy. The traffic mode was set to “car,” and the routing mode was set to “fast”, which ignores real-time traffic. This code was run twice, obtaining 30-minute and 15-minute isolines. 

### Calculating populations
We used block group population data from the [US Census Bureau 2024 ACS 5-year estimates](https://data.census.gov/table/ACSDT1Y2024.B01003?q=B01003&g=040XX00US29) using the Census API. We used the [2024 US Census Bureau TIGER/Line shapefiles](https://www.census.gov/geographies/mapping-files/time-series/geo/tiger-line-file.html) to get a block group shapefile, which include land area (ALAND) and water area (AWATER) for each block group. See [scripts/003_get_population.R](scripts/003_get_population.R). 
In [scripts/004_calculations.R](scripts/004_calculations.R), population estimates and block group geometries (mo_population_block.geojson), as well as isoline files (isolines_30_min.geojson and isolines_15_min.geojson) were transformed to the Missouri Central projection 26997. All isolines were then merged into a single unified coverage shape. Afterwards, we found and calculated the area of intersections between block groups and drive time isolines. The percentage of covered area was derived through dividing covered area by total land area for each block group. Based on the assumption that population was spread evenly across each block group, we multiplied this covered area percentage by population estimates to get the percentage of people who live within a particular drive time to a pharmacy. We used this percentage to estimate the number of people who live within pharmacy deserts in the state.

### Mapping block groups by uncovered populations
In [scripts/005_viz.R](scripts/005_viz.R) we mapped the block groups in the Missouri Central projection 26997 and used ggplot to shade block groups according to the raw population in each block group estimated to be outside of our drive-time polygons. 

### Important caveats
Though the methodology uses accepted practices, there are some caveats that result in these numbers being estimates and not exact calculations. The population for each block group has a “margin of error” which can sometimes be significant (i.e. the bureau estimates that 1000 people live in a block group but there’s a 90% change the number actually falls between 750 and 1250). We checked our analysis using the low end of the population estimate for all block groups and the numbers still supported the story. The analysis also assumes that the population of a block group is evenly distributed over the land portion of the block group, which could either underestimate or overestimate the population within range of a pharmacy. Therefore these numbers should be taken as estimates, their value most accurate in the aggregate.
